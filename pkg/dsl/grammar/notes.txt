LEXICAL TOKENS

  Ident     a letter or _ followed by letters, digits and _. This grammar has
            no lexical keywords: every word above lexes as an Ident and the
            parser decides what it meant from its position. So `body`, `get`
            and `contains` are all legal variable and capture names.
  Number    123, 3.5, 1e9. No leading +.
  String    "..." with \" \\ \n \r \t \$ as its escapes, and ${ Expr } for
            interpolation: "${base}/orders/${id}". A ${ with no } is an error
            with a span on the ${.
  Regex     /pattern/, with \/ for a literal slash. Go regexp syntax. It must
            compile, and that is checked when the file is parsed, not when it
            runs.
  Bool      true or false.
  Comment   # to the end of the line. Comments and blank lines are retained:
            `artemis fmt` and a UI writing a file back preserve them.

SEPARATORS

  Statements separate by a newline. A comma does as well, so a block may be
  written on one line: `retry { times = 3, delay = "1s" }`. There are no
  semicolons. A trailing comma is permitted in an object and in an array.

PRECEDENCE, loosest first

  or
  and
  not                      (prefix)
  == != < <= > >=  contains  matches  exists  is    (non-associative)
  -                        (prefix)
  .  []                    (postfix)

  `not` binds looser than `exists` and `is`, so `not body.x exists` means
  `not (body.x exists)`. It binds tighter than `and` and `or`, so
  `not a and b` means `(not a) and b`. A comparison does not chain:
  `a == b == c` is an error rather than a guess.

WHAT THE GRAMMAR DOES NOT SAY

  Field names are checked after parsing, not during it, so a typo gets
  "unknown field "quer": did you mean "query"?" with a one-click fix rather
  than a syntax error. The same is true of a config subject, a browser
  action's name, a type name after `is`, and a builtin's name.

  A step's type comes from its action block -- an HTTP verb makes it api,
  `run` makes it terminal, `browser` makes it browser -- and the type decides
  which names resolve inside it. A step has exactly one action block and it
  comes first.

  `timeout` and a `retry` block bound the whole step. `within` bounds one
  assertion: `expect text(".total") contains "Pro" within "10s"` re-evaluates
  that one expression until it holds or the budget runs out. A browser step's
  assertions default to a 5s `within`; api and terminal assertions are
  evaluated once.

  A duration is a string of a number and a unit: "30s", "500ms", "2m". A
  string in a duration position that is not one is a compile error.

  A collection holds requests and flows that a scenario reuses:

    import "collections/auth.art"           # relative to this file

    scenario "bad password" {
      use auth.login {                       # collection.item
        user = "alice"                       # an argument, by name
        password = "wrong"
        drop expects                         # the template's expects go,
        drop captures                        # its captures too: a 401 has no token
        expect status == 401                 # and this one is added
      }
    }

  A use is expanded into plain steps before the file is checked; `artemis
  expand` prints what will run. Arguments are passed by name. A use line that
  opens with header, query, body, drop, expect or in is an override, so a
  parameter may not be named one of those. `as rush` names the step "rush"
  and prefixes the captures the use makes with rush_. A bare `use item`
  names a sibling and is legal only inside a collection. Imports are not
  transitive. A template may read only its parameters, its observation and
  earlier captures in the same flow.

  A capture may not reuse a var's name or an earlier capture's name.

  There is no control flow: no conditionals, no loops, no functions. That is
  deliberate, and the Reserved list above is what keeps the door open.
